# CLAUDE.md

## WHY

Проект представляет собой HR-дайджест на базе Astro.

Цель проекта — публиковать материалы по подбору персонала, адаптации,
мотивации и развитию сотрудников.

Аудитория — HR-специалисты, рекрутеры и руководители.

## WHAT

Контент — это Astro Content Collection `blog`. Статьи лежат в
`src/content/blog/` как Markdown-файлы; просто положить файл в папку
недостаточно — его проверяет коллекция.

Frontmatter каждой статьи валидируется Zod-схемой (`src/content.config.ts`).
Обязательные поля: `title`, `description`, `pubDate`. Необязательные:
`cover`, `category`, `tags`, `source`, `updatedDate`.

Адрес страницы статьи строится из имени файла через
`src/pages/blog/[...slug].astro`. Переименование файла меняет URL —
проверяй ссылки.

В `astro.config.mjs` стоит placeholder `https://example.com` — при деплое
заменить на реальный домен.

## HOW

**Стиль статей.** Без обращения на «ты». Абзац — не длиннее четырёх строк.
Не начинать статью вопросом к читателю. Объём 300–500 слов.

- Перед изменением файлов изучай существующую структуру проекта.
- Не изменяй архитектуру без необходимости.
- Не изменяй `.env`.
- Если информации недостаточно — сначала задай уточняющий вопрос.
- После выполнения задачи кратко объясняй изменения.

## Content Style

Стиль статей — разговорный, чтобы материал читался как корпоративный блог, а не как инструкция. Стиль выбран потому, что статьи HR-дайджеста должны быть понятны HR-специалистам без академической подготовки.

Правила, по которым проверяется стиль каждой статьи:

1. **Объём** — статья содержит 300–500 слов. Нарушение: статья короче 300 или длиннее 500 слов.
2. **Абзацы** — каждый абзац не длиннее четырёх строк. Нарушение: абзац занимает пять и более строк.
3. **Обращение** — текст обращается к читателю на «вы». Нарушение: в тексте есть обращение на «ты».
4. **Первое лицо** — в тексте есть хотя бы одна форма первого лица единственного числа («я заметила», «я часто вижу») или множественного («мы используем», «мы рекомендуем»). Нарушение: в статье нет ни одной формы первого лица.
5. **Начало** — статья не начинается вопросом к читателю. Нарушение: первое предложение статьи — вопрос.
6. **Эмодзи** — в статье не более двух эмодзи. Нарушение: в тексте три и более эмодзи.
7. **Канцелярит** — в тексте нет канцелярских оборотов («в данном материале рассматривается», «следует отметить, что», «необходимо обратить внимание»). Нарушение: в тексте встречен хотя бы один такой оборот.
8. **Формулировки** — пункты правил можно проверить по «да/нет», формулировки «пиши живо», «делай дружелюбно» не используются. Нарушение: встретилось правило, по которому нельзя назвать конкретный нарушающий результат.

## Критерии отбора новостей

Тема подходит для публикации, только если по каждому пункту ответ «да».
Нарушение — хотя бы по одному пункту ответ «нет», тема в выпуск не идёт.

1. **HR-релевантность** — тема относится к подбору, адаптации, мотивации или развитию сотрудников. Нарушение: тема не связана с HR.
2. **Категория** — тема относится к одной из пяти категорий: Адаптация, Вовлечённость, Найм, Удержание, Технологии. Нарушение: тема не входит ни в одну категорию.
3. **Свежесть** — тема не публиковалась в дайджесте за последние 8 недель. Нарушение: идентичная тема уже выходила менее 8 недель назад.
4. **Практичность** — тема содержит действие, которое HR-специалист может применить в работе. Нарушение: тема чисто теоретическая, без практического вывода.
5. **Доказательность** — у темы есть источник: исследование, эксперт, кейс или статистика. Нарушение: тема основана на догадке без источника.

## Редполитика

Редакционные правила о том, какой материал acceptable для публикации.
Нарушение — встретилось хотя бы одно недопустимое содержание.

1. **Нейтральность компаний** — конкретные компании упоминаются как нейтральный пример, без оценок «хороший/плохой работодатель». Нарушение: компания оценена в позитивном или негативном ключе.
2. **Без дискриминации** — текст не содержит характеристик по полу, возрасту, национальности, религии, инвалидности или семейному положению. Нарушение: встретилась такая характеристика.
3. **Без рекламы** — текст не продвигает платные продукты или услуги конкретных вендоров. Нарушение: встретилась прямая рекомендация платного продукта конкретного вендора.
4. **Проверяемость фактов** — каждый значимый факт имеет ссылку на источник в поле `source` или в тексте. Нарушение: значимый факт приведён без ссылки на источник.
5. **Позиция пользы** — тема раскрыта с позиции пользы для HR-специалиста, а не позиции рекламы конкретного решения. Нарушение: материал построен вокруг продвижения одного решения.

## Digest Pipeline

Автоматический AI-дайджест: запуск по cron (понедельник 07:00 UTC) и вручную, генерация одной статьи за прогон, публикация через PR с ревью. Правила проверяются по «да/нет».

1. **Количество новостей** — за один прогон генерируется и публикуется одна статья. Нарушение: за прогон создаётся более одной статьи.
2. **Критерии отбора** — тема проходит отбор по пяти критериям: HR-релевантность, категория, свежесть, практичность, доказательность. Полный список — в разделе «Критерии отбора новостей». Нарушение: тема не прошла хотя бы один критерий.
3. **Формат и объём статьи** — статья содержит 300–500 слов, стиль разговорный, без обращения на «ты», абзац не длиннее четырёх строк, не более двух эмодзи. Полный список — в разделе «Content Style». Нарушение: статья короче 300 или длиннее 500 слов.
4. **Путь и имя файла** — статья сохраняется в `src/content/blog/`. Имя файла: `YYYY-MM-DD-<slug>.md`, где `<slug>` — латиница в kebab-case. Дата в имени файла совпадает с `pubDate`. Переименование файла меняет URL. Нарушение: файл лежит не в `src/content/blog/` или имя не соответствует формату.
5. **Редакционная политика** — материал соответствует пяти правилам: нейтральность компаний, без дискриминации, без рекламы, проверяемость фактов, позиция пользы. Полный список — в разделе «Редполитика». Нарушение: встретилось нарушение хотя бы одного правила.
6. **Обложка** — размер 1200×630 пикселей. Путь к обложке указывается в поле `cover` frontmatter, файл лежит в `public/covers/`. Нарушение: обложка не 1200×630 или путь не указан.

## Git Conventions

- Commits: Conventional Commits format.
- Types: feat, fix, docs, refactor, test, chore.
- Format: type(scope): description.
- Max subject line: 72 characters.
- Branch naming: type/short-description.
- PRs: always target "main".
